Marking guide (for assessors)

Part A answers

  1. B. <!doctype html> The doctype tells the browser to read the page as modern HTML5.
  2. B. Screen readers and search engines don’t know it’s a heading Only heading elements create a heading outline that screen readers can navigate.
  3. C. Download the 2026 leave policy (PDF) Link text should make sense on its own, out of context.
  4. C. alt="" An empty alt tells screen readers to skip it.
  5. B. It disappears when people type and is not reliably read as a name Use a visible label linked to the field with for and id.

Part B model answers

  1. Choosing each element for what the content is, not how it looks; for example, using <h2> for a section heading instead of bold text.
  2. A caption that names it, header cells with <th> and scope="col" or scope="row", and header rows in <thead>.

Part C: look for

  • Uses one <h1> and a logical heading outline
  • Writes alt text that describes the venue photo for this purpose
  • Rewrites the link text to say where it goes
  • Marks up the timetable as a table with a caption and header cells
  • Adds visible labels and a real submit button to the form

Result: all Part D criteria observed, and Parts A to C answered to the standard above. Where something is not yet shown, give feedback and agree a time to reassess.
